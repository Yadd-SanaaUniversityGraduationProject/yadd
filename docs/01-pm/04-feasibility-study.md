# دراسة الجدوى — Feasibility Study

> **الحالة:** `SKELETON — DATA REQUIRED`
>
> لا توضع أرقام تكلفة أو ادعاءات قدرة تقنية دون دليل.

## 1. Economic Feasibility

### البيانات المطلوبة
- تكلفة الاستضافة/الخادم في سيناريو MVP.
- تكلفة خدمات الخرائط/الرسائل/التخزين إن وجدت.
- تكلفة أي API للذكاء الاصطناعي المقترح.
- تكلفة النشر/الاختبار والأجهزة المتاحة للفريق.
- هل الاشتراك جزء من MVP أم نموذج لاحق؟ `SUB-Q01`.

### المخرج المطلوب
جدول تكلفة تقديرية موثق + تفسير لماذا النطاق المختار مناسب لمشروع التخرج.

## 2. Technical Feasibility

### خيارات حالية — `PROPOSED`
- Flutter.
- ASP.NET Core API.
- GitHub.
- API-based AI إذا بقي في MVP.

### أسئلة التقييم
- خبرة الفريق الفعلية بكل تقنية.
- قابلية إنجاز Core flows خلال الزمن المتاح.
- متطلبات الاتصال في صنعاء.
- تخزين الوسائط وحجمها.
- الموقع الجغرافي والإشعارات.
- الخصوصية والأمن، خصوصًا بيانات الهوية والوجه.

## 3. Operational Feasibility

يلزم التحقق ميدانيًا من:
- قدرة المستخدم المستهدف على إنشاء طلب/عرض/فاتورة بسهولة.
- توفر هاتف واتصال ملائمين.
- وضوح المصطلحات والأسعار والتقييم.
- قبول التحقق من الهوية إن بقي ضمن MVP.

## 4. قرار الجدوى

لا يوضع `FEASIBLE` حتى تملأ البيانات السابقة وتراجع من الفريق. النتيجة الحالية: `NEEDS_VERIFICATION`.
