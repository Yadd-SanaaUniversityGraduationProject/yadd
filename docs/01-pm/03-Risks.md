## Change Control

1. التغيير الذي يغير معنى المشروع يسجل في Decision Register أو Open Questions حسب حالته.
2. تغييرات الجدول وتوزيع العمل التي لا تغير Scope/Requirements تسجل في Work Plan وتزامن مع Risk/Document Register.
3. لا يرفع SRS إلى `APPROVED/BASELINED` إلا بعد مراجعة الفريق وإغلاق الحواجز المطلوبة.
4. أي تغيير معتمد يؤثر على Requirement يجب أن يحدث Traceability Matrix والرسومات والتصميم المتأثر.
5. مخرجات `DRAFT FOR PRELIMINARY DEFENSE` ليست Baseline نهائيًا؛ تستخدم للمناقشة ثم تحدث وفق التغذية الراجعة.
6. لا تستخدم GitHub Issues القديمة أو خطة الأسبوعين السابقة كمصدر لتوزيع العمل أو المواعيد.
