# حوكمة وثائق مشروع يَد | YADD

> **الغرض:** جعل المستودع مصدر الحقيقة قبل استخراج الفصول الأكاديمية.

## ترتيب القراءة

1. `01-university-requirements-map.md` — ما الذي تطلبه الجامعة وما أثره على وثائقنا.
2. `02-decision-register.md` — القرارات المعتمدة والمقترحات والأسئلة غير المحسومة.
3. `03-open-questions.md` — القرارات التي يجب حسمها بسرعة.
4. `04-document-register.md` — حالة كل مخرج مطلوب.
5. `05-two-week-plan.md` — خطة التنفيذ حتى موعد التسليم.
6. `06-readiness-checklist.md` — بوابة تمنع البدء بالفصول قبل اكتمال الأساس.

## مبدأ Single Source of Truth

- القرار يوثق مرة واحدة في Decision Register ثم تشير إليه بقية الوثائق بالرمز.
- المتطلب يوثق مرة واحدة في SRS ثم تستخدم النماذج والتصميم معرف المتطلب نفسه.
- قواعد العمل توثق في Business Rules ولا تعاد صياغتها بشكل متناقض في المخططات.
- نتائج المقابلات/الملاحظة لا تدخل كحقائق إلا بعد توثيق دليل جمع البيانات.
- الفصل الأكاديمي مخرج مشتق، وليس وثيقة تشغيلية لإدارة المتطلبات.

## قاعدة تغيير الحالة

`PROPOSED → ANALYZED → APPROVED` لا يحدث تلقائيًا. يجب أن يوجد قرار مراجعة واضح من الفريق، مع التاريخ والمسؤول في سجل القرارات.
